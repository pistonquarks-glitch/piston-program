# ADR-0003: Capability Protocol y adaptadores externos

## Estado

Aceptado.

## Problema

Los agentes no deben depender de MCP, CLI, REST, GraphQL, gRPC, SDKs ni proveedores concretos.

## Alternativas consideradas

1. Integrar cada protocolo directamente en los agentes.
2. Construir un traductor central que interprete todos los formatos de dominio.
3. Definir un protocolo interno de capacidades y adaptar cada integración externamente.

## Decisión

`@piston/protocol` definirá contratos versionados para capacidades, solicitudes, resultados, eventos, artefactos, errores y manifiestos. Cada protocolo o proveedor externo se implementará como extensión.

## Consecuencias

El Traductor Universal queda limitado a normalizar capacidades, no a interpretar formatos de dominio. Se podrá reemplazar una integración sin modificar agentes ni product packs.
